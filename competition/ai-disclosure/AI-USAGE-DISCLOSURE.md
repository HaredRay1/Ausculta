## 1. Was generative AI used?

**Yes, extensively.** It would be misleading to answer this narrowly. Generative AI wrote
essentially all of the project's software.

## 2. What tool was used

| | |
|---|---|
| Tool | Claude (Anthropic), used through Claude Code, an agent-based coding environment |
| Model | Claude Opus 5 |
| Period of use | 28–29 August 2026 |
| How | Interactive dialogue with a project maintainer, plus multiple AI agents working in parallel on separate parts of the codebase under that maintainer's direction |

The AI wrote code and documents directly into the repository. All 144 commits on the
application branch are recorded under the maintainer's git identity because that is the
configured author of the checkout; **the content of those commits was generated by AI**,
with the maintainer directing, reviewing, accepting and rejecting the work.

## 3. Which elements of the project used AI

### Written by AI

- **The entire mobile application** (`app/`) — every screen, all data handling, the
  authentication and role system, the offline database, the bilingual text, and the
  approximately 2,000 automated tests. React, TypeScript.
- **The audio and inference pipeline** — the code that reads a recording, checks whether it
  is usable, and runs the machine-learning model on the device.
- **The ESP32 device firmware** (`firmware/`) — audio capture, WAV file writing, the display
  and controls.
- **The 22 instructional diagrams** (`app/public/guides/`) — drawn as SVG by AI.
- **Project documentation** — architecture notes, README files, the build status report, and
  the validator orientation sheet.
- **A literature review** informing the rehabilitation module's content — AI searched and
  summarised published guidance, with citations. **That content has not been reviewed by a
  clinician and is marked in the app as pending review.**
- **This disclosure document.**

### Not written by AI, to the team's knowledge

- The research paper and competition documents.
- The fieldwork: clinic interviews, consent, and the study design.
- The machine-learning model itself, trained by the team in Edge Impulse Studio on a public
  respiratory sound database. The AI integrated the exported model but did not create,
  train or modify it.
- The hardware design and physical build.

*The team must confirm this list.*

### Where AI changed the project's direction

Three points where AI analysis altered decisions, which the team should be able to explain:

1. **A clinical error in the project's own specification.** The specification listed huff
   coughing as a rehabilitation activity. AI literature review found it belongs to a mucus
   clearance protocol evidenced for cystic fibrosis and COPD, and is contraindicated in
   bronchospasm — the condition this app targets. It was excluded and the reasoning recorded.
2. **A hardware fault.** AI identified that the wiring diagram routes the indicator LED to
   an input-only pin on the ESP32, where it can never light. The firmware uses a different
   pin.
3. **Model behaviour.** AI testing established that the trained model reports silence as
   "Healthy" at 98.8% confidence and noise as "Asthma" at 99.6%. This produced the quality
   gate that refuses to analyse unusable recordings.

## 4. What AI did not decide

Held for human judgement and documented as open in `STATUS.md`:

- Whether recording should be blocked without recorded consent — an ethics decision.
- The rehabilitation exercise instructions, three unverified citations, two oxygen
  thresholds in patient-facing text, the anatomical positions in the placement diagrams,
  and the consent text — all await a clinician.
- The Filipino translation of clinical, consent and safety text, which the project's own
  rules require a qualified human translator and practitioner review to produce. AI drafted
  interface text only and left clinical text in English.

## 5. Honest limitations of the AI-written software

- The model is roughly 71% accurate, trained on public data, never validated on recordings
  from this device or these patients.
- Nothing has been clinically validated.
- No AI agent could operate the app on a real device; the software was verified by automated
  tests and code analysis. A human tester found two significant defects within five minutes
  of installing it that this testing had missed.
